**Method review of `implementation/audit_ordinary_trainer_wiring.py` (static inspection, not run):**
1. The script checks only Trainer initializer presence, class and `.doubleBattle`; it **never parses the actual party-array definitions**, slot count, name, portrait, AI or equipment. `RE_INIT` requires a rigid `\\n    },` initializer terminator and risks missed/incorrect entries if formatting changes.
2. Its `references` set matches any Trainer token anywhere in all scripts, including comments, text or unrelated references. An original ID appearing there is **not** evidence that a reachable `trainerbattle` command exists. Conversely, dynamically selected trainer IDs may be reachable without a literal reference.
3. `script_labels` is a single repository-wide set. Seeing a label defined somewhere does **not** establish that the corresponding map loads/imports that script label, or that a particular NPC object maps to the expected Trainer ID, position, defeat flag or reachable event path. Labels on `TRAINER_TYPE_NONE` scripted objects are not assessed.
4. The rematch check looks for the base ID plus a `trainerbattle_rematch(?:_double)?` token anywhere in the script corpus, rather than verifying the correct original event label, local NPC, map, defeat-flag identity or runtime VS Seeker eligibility. The collected `RE_BATTLE` regex is declared but not used. Special paired Double encounter behavior is not independently validated.
5. `RE_VS` takes distinct variant IDs across recognized array rows and overwrites duplicates silently; there is no collision report or independent verification that the map named in the VS Seeker row is the live map containing the base NPC. Its pattern may miss atypically formatted/macro-provided table rows.
6. `ROW` and `RVAR` assume exact Markdown table formatting and `ROW` accepts duplicate keys by overwriting them. The result should report duplicate IDs, unparsed rows, and status anomalies rather than trusting map size alone.
7. `map.json` verification only tests that a nonempty Trainer object's script label exists somewhere; it does not test object type, `trainer_type` semantics, coordinate, sight range, flag relationships, graphic/class compatibility, or any unused battle scripts. Missing script strings and dynamic/indirect dispatch require an explicit unknown category, not automatic pass.
